Panduan Instalasi Argen

Auto Article Generator: artikel otomatis per kata kunci dan wilayah, ditulis AI lokal (Ollama). Untuk komputer Windows baru yang belum punya Laragon maupun Ollama. Diperbarui 27 Oktober 2026.

Kebutuhan

KomponenFungsiUkuran

Model AIPenulis artikel2–5 GB per model

Disarankan: Windows 10/11, RAM minimal 8 GB (16 GB lebih nyaman), ruang kosong 10 GB, dan internet saat instalasi. Model 3B berjalan di CPU biasa, tetapi lebih cepat bila ada GPU.

1Pasang Laragon

  1. Unduh Laragon Full dari laragon.org/download.
  2. Jalankan installer dan pakai lokasi bawaan C:\laragon.
  3. Setelah selesai, buka Laragon lalu klik Start All. Layanan web server dan MySQL harus berjalan.
Jika Windows Firewall bertanya, pilih Allow access.

2Pasang aplikasi

Salin seluruh folder aplikasi ini ke:

C:\laragon\www\argen

Pastikan index.php, settings.php, generate.php, process.php, dan config.php berada langsung di dalam folder argen, bukan di subfolder lagi.

3Cek port MySQL

Aplikasi diatur memakai MySQL di port 3309, sedangkan bawaan Laragon biasanya 3306. Pilih salah satu cara:

Opsi A (paling mudah): sesuaikan aplikasi

  1. Di Laragon buka Menu > Preferences > Services & Ports dan lihat port MySQL (misalnya 3306).
  2. Salin config.local.example.php menjadi config.local.php di folder aplikasi, lalu isi barisnya:
define('DB_PORT', 3306);   // samakan dengan port MySQL di Laragon

Jika config.local.php tidak dibuat, aplikasi memakai bawaan config.php (port 3309).

Opsi B: sesuaikan Laragon

Ubah port MySQL di Preferences > Services & Ports menjadi 3309, lalu Stop All dan Start All.

Jika root MySQL Anda memakai password, isi juga DB_PASS di config.local.php.

4Database

Tidak perlu membuat database manual. Saat aplikasi pertama kali dibuka, database argen dan semua tabelnya (wilayah, master_templates, master_shortkeys) dibuat otomatis.

5Pasang Ollama

  1. Unduh installer Windows dari ollama.com/download.
  2. Jalankan installer sampai selesai. Ollama berjalan di latar belakang (ikon llama di system tray dekat jam) pada http://127.0.0.1:11434.
  3. Cek berhasil: buka http://127.0.0.1:11434 di browser. Harus muncul tulisan Ollama is running.

6Unduh model AI

Buka PowerShell atau Command Prompt, lalu jalankan (cukup sekali, butuh internet):

ollama pull qwen2.5:3b
PerintahKeterangan
ollama pull qwen2.5:3bCepat dan ringan, paham bahasa Indonesia. Disarankan untuk mulai.
ollama pull llama3.2:3bRingan, kualitas bahasa Indonesia cukup.
ollama pull llama3:8bLebih bagus, tetapi butuh RAM ± 8 GB dan lebih lambat.
Hindari model khusus kode (misalnya qwen2.5-coder); tulisannya kurang baik untuk artikel.

Cek model yang terpasang:

ollama list

7Jalankan aplikasi

  1. Pastikan Laragon Start All dan Ollama aktif.
  2. Buka browser ke http://localhost/argen/. Setelah klik kanan Laragon > Apache/Nginx > Reload, bisa juga http://argen.test.
  3. Pertama kali dibuka, aplikasi meminta membuat akun admin (username dan kata sandi min. 10 karakter). Dari komputer yang sama dengan server, tidak perlu kunci setup. Akun berikutnya ditambah di menu nama akun.
  4. Dropdown Model Ollama terisi otomatis dari model yang terpasang. Jika kosong, lihat pemecahan masalah.

Cara pakai singkat

  1. Buka ⚙ Pengaturan dan isi data master:
    • Wilayah: tambah satu per satu, atau import massal (satu baris Provinsi|Kota/Kab|Kecamatan|Kelurahan, boleh tempel dari Excel).
    • Shortkey: buat kata pintas sendiri, misalnya cta, lalu panggil dengan {cta}.
    • Template: simpan template artikel yang sering dipakai.
    • Sumber Web: tentukan dari mana AI mengambil bahan. Bawaan: Wikipedia Indonesia. Bisa menambah wiki lain (mis. en.wikipedia.org), pencarian web (Bing, bisa dibatasi ke satu situs), atau alamat halaman dengan {q}. Gunakan tombol Uji untuk melihat apa yang berhasil diambil. Makin banyak sumber relevan, makin kaya isi artikel.
  2. Kembali ke halaman utama, isi Daftar Kata Kunci (satu per baris). Setiap kata kunci dikombinasikan dengan setiap kelurahan pada Target Wilayah: 2 kata kunci × 3 kelurahan = 6 artikel, masing-masing disimpan terpisah. Batas Jumlah Artikel per Proses (awal 50) mencegah satu kota langsung membuat ratusan artikel.
  3. Pilih Target Wilayah dan Model Ollama.
  4. Pilih template master (judul dan isinya terisi sekaligus) atau tulis sendiri di kartu Template Artikel: kolom Judul Artikel (boleh memakai {judul} agar judulnya ditulis AI) dan kolom Isi Artikel.
  5. Klik Proses & Generate Artikel. Hasil muncul di Hasil Preview dan otomatis tersimpan; lihat semuanya di 📄 Artikel (cari, baca, salin, hapus).

Cara kerja & tips kualitas

Setiap artikel dibuat dengan urutan berikut, supaya paragrafnya saling nyambung dan tidak mengarang:

  1. Bahan: aplikasi mengambil referensi dari Sumber Web yang aktif (bawaan Wikipedia Indonesia) untuk kata kunci dan untuk wilayahnya.
  2. Kerangka: AI menyusun satu kalimat maksud keseluruhan artikel dan satu pokok bahasan berbeda untuk tiap {paragraf}.
  3. Judul: bila judul memakai {judul}, AI menulisnya setelah kerangka jadi, sehingga selaras dengan isi.
  4. Paragraf: tiap {paragraf} ditulis berurutan, tahu peran dan pokok bahasannya (pembuka, lanjutan, penutup) serta teks sebelumnya.
  5. Pembersihan & simpan: label, kalimat meta, nomor telepon/email/URL karangan, dan aksara asing dibuang; paragraf dibatasi 5 kalimat. Hasil disimpan ke database.

Tips supaya hasilnya bagus

  • Pakai model umum seperti qwen2.5:7b (RAM 16 GB) atau qwen2.5:3b (lebih ringan), bukan model khusus kode.
  • Aktifkan Pencarian Web (Bing) di Pengaturan > Sumber Web untuk kata kunci niaga yang tidak ada di Wikipedia. Uji dulu dengan tombol Uji.
  • Tulis fakta usaha sendiri (nama usaha, harga, alamat, kontak, promo) langsung di template, di antara {paragraf}. AI hanya diminta menulis hal umum yang didukung referensi dan dilarang mengarang kontak atau klaim "terbaik/termurah".
  • Kurangi jumlah {paragraf} (mis. 2) bila ingin lebih cepat dan minim karangan. Satu {paragraf} sekitar 45 detik pada model 7B.
  • Beri arahan pada {paragraf: ...} dan {judul: ...} untuk hasil yang lebih terarah.

Tema tampilan

Di pojok kanan menu atas ada pengalih Gelap / Terang / Auto. Gelap adalah tampilan awal; Auto mengikuti pengaturan Windows/browser. Pilihan tersimpan di browser dan berlaku di semua halaman, termasuk panduan ini. Untuk pratinjau, tambahkan ?theme=light atau ?theme=dark di alamat halaman.

Publikasi ke WordPress

Artikel dikirim lewat REST API bawaan WordPress memakai Application Password. Cocok untuk shared hosting: tidak perlu plugin dan tidak perlu FTP.

  1. Di WordPress: Pengguna > Profil Anda > Application Passwords, isi nama (mis. Argen), klik Add New Application Password, salin passwordnya.
  2. Di Argen: ⚙ Pengaturan > WordPress. Isi alamat situs (https://situsanda.com), username, Application Password, status bawaan, kategori, dan zona waktu. Klik Simpan lalu Uji koneksi.
  3. Di halaman utama, isi bagian Publikasi WordPress: tanggal publish artikel pertama, jarak antar artikel, dan status. Centang Kirim otomatis bila mau langsung terkirim, atau kirim nanti dari 📄 Artikel.
Status + tanggalHasil di WordPress
Terbit + tanggal masa depanTerjadwal (future), terbit otomatis pada waktunya
Terbit + tanggal lampauLangsung terbit dengan tanggal mundur (backdate)
Terbit tanpa tanggalTerbit saat dikirim
Draft / Review / Privat + tanggalTersimpan dengan tanggal itu, tidak diterbitkan

Password yang dipakai

Isi kolom password dengan Application Password, bukan password login. Bentuknya 24 karakter dalam 6 kelompok, mis. abcd efgh ijkl mnop qrst uvwx, dan hanya tampil sekali saat dibuat. Username diisi username WordPress (bukan email), dan alamat situs harus https://.

Jika uji koneksi gagal (401)

CekPenjelasan dan perbaikan
Alamat memakai http://Application Password hanya aktif di HTTPS. Ganti alamat menjadi https://situsanda.com.
Password bukan 24 karakterYang tersimpan kemungkinan password login atau tersalin tidak utuh. Buat Application Password baru di Pengguna > Profil Anda dan salin seluruhnya.
Header login dibuang hostingGejalanya: password palsu pun dijawab "belum login", bukan "password salah". Umum di hosting LiteSpeed/CGI. Tambahkan baris berikut di .htaccess folder utama WordPress (yang berisi wp-config.php), di atas baris # BEGIN WordPress, bukan di bawahnya.
Cache / plugin keamananKosongkan cache LiteSpeed. Pastikan plugin keamanan (Wordfence, Solid Security, "Disable REST API") atau ModSecurity/Imunify360 tidak menonaktifkan Application Password atau memblokir header Authorization.
# --- teruskan header login ---
<IfModule mod_rewrite.c>
RewriteEngine On
RewriteCond %{HTTP:Authorization} .
RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
</IfModule>
SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
# --- akhir ---

# BEGIN WordPress
...(isi bawaan WordPress, jangan diubah)...
# END WordPress
Jika 403, plugin keamanan atau firewall hosting kemungkinan memblokir REST API, atau akun tidak berhak menulis post (gunakan Administrator/Editor). Pesan error di Argen sudah menyebut penyebab yang paling mungkin, termasuk peringatan otomatis bila alamat masih http:// atau password bukan 24 karakter.
Artikel terjadwal diterbitkan oleh WP-Cron, yang berjalan saat situs dikunjungi. Di situs sepi, terbitnya bisa terlambat; pasang cron job asli di hosting yang memanggil wp-cron.php bila perlu ketepatan waktu. Situs harus memakai HTTPS agar Application Password aktif.

Pasang di VPS (online)

Panduan ini untuk Ubuntu 24.04 dengan Nginx, PHP-FPM, MariaDB, dan Ollama dalam satu server. Contoh spesifikasi: 2 core CPU, RAM 8 GB. Ganti contoh.com dengan domain Anda.

Langkah dan angka di bagian ini belum diuji di VPS sungguhan; fitur login, pembatasan akses, dan pengaturan AI sudah diuji di Laragon. Jalankan langkah satu per satu dan cek hasilnya sebelum lanjut.

Yang realistis untuk 2 core / 8 GB

HalSaran
Modelqwen2.5:3b (sekitar 2 GB). Model qwen2.5:7b muat di RAM tetapi di 2 core CPU sangat lambat (satu artikel bisa belasan menit) dan sisa RAM tipis.
Pengaturan > AIKonteks 4096, batas waktu 600 detik, model bertahan 30m.
PenggunaanSatu pembuatan artikel pada satu waktu. Tab browser harus tetap terbuka selama proses berjalan.
SwapTambahkan 4 GB sebagai pengaman agar server tidak mati saat RAM penuh.

1. Siapkan server

sudo apt update && sudo apt -y upgrade
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable

# swap 4 GB
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Jangan membuka port 11434 (Ollama) dan 3306 (database) ke internet. Firewall di atas sudah hanya membuka SSH, 80, dan 443.

2. Pasang paket

sudo apt -y install nginx mariadb-server git unzip curl \
  php-fpm php-cli php-mysql php-curl php-mbstring certbot python3-certbot-nginx

3. Database

sudo mysql -e "CREATE DATABASE argen CHARACTER SET utf8mb4;
CREATE USER 'argen'@'localhost' IDENTIFIED BY 'GANTI_SANDI_KUAT';
GRANT ALL PRIVILEGES ON argen.* TO 'argen'@'localhost';"

Tabel dibuat otomatis oleh aplikasi saat pertama dibuka.

4. Ollama

curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl edit ollama

Pada editor yang terbuka, isi (batasi agar tidak membebani RAM dan hanya melayani lokal):

[Service]
Environment="OLLAMA_HOST=127.0.0.1:11434"
Environment="OLLAMA_NUM_PARALLEL=1"
Environment="OLLAMA_MAX_LOADED_MODELS=1"
sudo systemctl restart ollama
ollama pull qwen2.5:3b

5. Pasang aplikasi

sudo git clone https://github.com/AbbySyailendra/argen.git /var/www/argen
cd /var/www/argen
sudo cp config.local.example.php config.local.php
sudo nano config.local.php      # isi DB_PASS, DB_PORT=3306, SETUP_KEY (teks acak panjang)
sudo chown -R www-data:www-data /var/www/argen
sudo chmod 640 config.local.php

config.local.php tidak ikut git dan berisi sandi, jadi hanya bisa dibaca pemilik dan www-data.

6. Nginx

sudo nano /etc/nginx/sites-available/argen
server {
    listen 80;
    server_name contoh.com;
    root /var/www/argen;
    index index.php;
    client_max_body_size 5m;

    # file sensitif: tidak boleh dibuka dari web
    location ~ ^/(config\.local(\.example)?|adduser)\.php$ { deny all; }
    location ~ /\.(?!well-known) { deny all; }

    location / { try_files $uri $uri/ =404; }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;   # sesuaikan versi PHP (php -v)
        fastcgi_read_timeout 900s;                    # satu permintaan AI bisa lama
    }
}
sudo ln -s /etc/nginx/sites-available/argen /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

7. HTTPS

Arahkan DNS domain (record A) ke IP server, lalu:

sudo certbot --nginx -d contoh.com

Gunakan HTTPS sebelum login dipakai. Tanpa HTTPS, kata sandi terkirim polos dan Application Password WordPress tidak aman.

8. Buat akun dan atur AI

  1. Cara aman dari terminal server: cd /var/www/argen && sudo -u www-data php adduser.php admin (masukkan kata sandi min. 10 karakter).
  2. Atau buka https://contoh.com/login.php, isi akun pertama beserta kunci setup (SETUP_KEY di config.local.php). Setelah ada akun, formulir pembuatan akun tertutup otomatis.
  3. Masuk, lalu buka Pengaturan > AI (Ollama): pastikan status Terhubung, pilih model qwen2.5:3b, konteks 4096, batas waktu 600. Simpan.
  4. Isi Pengaturan > WordPress, lalu uji koneksi. Di server yang bisa mengirim header dengan benar, masalah 401 dari hosting kecil kemungkinan muncul.

Pemecahan masalah

GejalaPenyebab dan solusi
"Koneksi Database Gagal"MySQL Laragon belum Start, atau port/password di config.php tidak sesuai (lihat langkah 3).
Halaman tidak terbuka (404)Folder harus bernama argen dan berada di C:\laragon\www\. Pastikan web server Laragon menyala.
Dropdown model kosong / "Ollama tidak terdeteksi"Ollama belum berjalan. Buka aplikasi Ollama dari Start Menu, cek http://127.0.0.1:11434, lalu muat ulang halaman.
"(gagal: model … not found)"Model belum diunduh. Jalankan ollama pull nama-model, lalu muat ulang halaman.
Proses sangat lambat atau timeoutKomputer kurang kuat untuk model itu. Pakai model lebih kecil (qwen2.5:3b), kurangi kata kunci, atau tutup aplikasi berat lain. Batas waktu per paragraf 120 detik.
Tampilan polos tanpa desainHalaman memuat Tailwind CSS dari internet. Pastikan komputer terhubung ke internet.
Data Wikipedia tidak munculNormal bila kata kunci tidak ada di Wikipedia Indonesia; AI memakai informasi umum. Perlu internet untuk mengambilnya.
"(gagal: …)" pada sebuah paragrafOllama mati/timeout, atau keluaran model rusak 3 kali berturut-turut (mis. berpindah ke bahasa Mandarin). Artikel tetap disimpan dengan tanda sebagian gagal; hapus lalu buat ulang, atau coba model lain.
Isi artikel memuat klaim yang tidak benarReferensinya terlalu sedikit sehingga model mengisi sendiri. Aktifkan Pencarian Web (Bing), tambah sumber, dan tulis fakta usaha langsung di template.
WordPress: "Login ditolak (401)"Lihat bagian Publikasi ke WordPress > "Jika uji koneksi gagal".
"Sesi berakhir" / kembali ke halaman loginTidak aktif lebih dari 8 jam atau akun dihapus. Masuk lagi. Di server, pastikan cookie tidak diblokir dan situs memakai satu alamat (jangan campur www dan tanpa www).
"Terlalu banyak percobaan gagal"Tunggu 15 menit, atau ganti sandi dari terminal: php adduser.php nama.
"Permintaan ditolak (asal tidak cocok)"Aplikasi dibuka lewat alamat yang berbeda dari alamat server (mis. reverse proxy yang mengubah header Host). Teruskan header Host asli di proxy.
502/504 di server saat membuat artikelBatas waktu Nginx/PHP-FPM terlalu pendek. Pakai fastcgi_read_timeout 900s dan sesuaikan batas waktu di Pengaturan > AI.
Ekstensi curl tidak adaLaragon Full sudah mengaktifkannya. Jika tidak, aktifkan extension=curl di Menu > PHP > php.ini, lalu Reload.
